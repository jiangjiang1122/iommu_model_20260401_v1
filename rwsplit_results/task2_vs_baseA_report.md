## 0. 前置说明：任务2 崩溃修复（本报告数据为修复后重跑结果）

任务2 原构建在 246744.229 ns 确定性崩溃（`Fatal: MULTIDEV: 两阶段聚合结果PTE无效`）。根因为 **dedup update 竞态 use-after-free**：外国组（group 75942）的预取结果经 dedup scheduler 无条件 flush 了仍在 PTW 行走、已建组（group 76100）的在途主任务占位链，导致主任务被提前释放、堆对象复用（task 77391）、组 main_task 悬垂，聚合结果 slot0 读到全零 PTE（V=0）。

修复（3 文件）：`dedup_cache.h` / `dedup_cache.cpp` 的 `DedupCacheLine` 增加 `owner_task_id` / `owner_suspended` 字段；`cache_subsystem.cpp` 在主占位 MISS 新建时登记 owner（仅自己的组可 flush），升级路径登记 owner_suspended（任意组结果可释放）；`execute_dedup_update` 增加外来组守卫（SKIP，不 flush 不 clear）。

修复后重跑：**PASS 160000/160000、Fatal=0、守卫真实触发 2 次**（`SKIP foreign update` 计数=2，证明按设计路径生效）。修复仅影响竞态路径的 flush 条件，不改变吞吐主路径，与基线A（单设备，竞态条件几乎不出现）可比。

## 10. 性能退化归因（吞吐 −19.3% 的因果链）

1. **工作集 16 倍，固定容量翻译资源被摊薄（根因）**
   - 16 个 GSCID 共享 256 行去重 Cache：valid 占用 47.4%→76.9%（峰值打满 256），hash 冲突率 0.08%→7.14%，bypass 任务 6→3434（占数据任务 2.95%）；去重命中率 87.63%→59.61%。
   - Walker C3（leaf 级，4KB 页级缓存）命中率 69.61%→23.02%（−46.6 pt），直接把主任务从"2 次 DDR"（69.6%）推向"7 次 DDR"（76.7%）。
   - 主任务平均 DDR 次数 3.57→5.90（+65%），其中 GS 二阶段 2.26→4.12（+82%）——S2/GVA 翻译的重复红利消失。
2. **PTW 成为共享瓶颈**
   - PTW 并发利用率 31.54%→71.18%，峰值 64/64 打满（饱和 100% vs 78.12%）。
   - 主任务执行延时 1168→1740 ns（+49%），组延时 1166→1738 ns；DDR 单次延时 avg 203.2→215.3 ns（排队 +6%）。
   - DDR 读流量 26.4 倍（每数据任务 0.87→1.44 次），master_1 并发峰值 95→186/256（仍未饱和，非 DDR 带宽瓶颈）。
3. **反压传导到端口层**
   - 出口变慢 → outstanding 持有变长（内部 Global 并发 346→405，Buffer hold avg 1197→2566 ns，MAIN MISS hold 1386→3799 ns）。
   - 写口门控阻塞占比 0.92%→10.04%（8762 次/233.7 us），写口顶满时长 20.3%→36.8%；读口顶满 1.1%→12.2%。
   - 注入期入口带宽 99.4→83.0 GB/s（−16.5%），写口节拍占比 81.5%→67.9%（线速利用下降）。
4. **吞吐与延时的最终平衡**：每包平均 e2e 几乎不变（1996.6→1990.9 ns）——16 倍并发把增大的服务延时（PTW/DDR 排队）摊进更高的在途并发（Global 内部 405/640），吞吐 = 并发/延时 = 404.73/1990.9 ns ≈ 203 M/s（内部口径），最终稳态吞吐 231.7 vs 287.0 Mreq/s（−19.3%）。max e2e +81.8%（11130 ns）反映排队尾延迟。
5. **公平性无损**：16 设备注入/完成完全均衡（10000/10000），Jain=0.999999；MDMC 供给器仅 R/W 各 1 次饥饿，RWQ 深度 65536 远未打满（峰值 87087）。

### 12.4 PT Cache 512B 数据命中率 58.74% 的机制（vs 基线A ≈0%）

根因：**128 流交织把组内 8 连发的注入间隔拉长了 15 倍，使后到者落在主 walk 完成之后**：

| | 基线A（8 流） | 任务2（128 流） |
|---|---|---|
| 组内相邻任务间隔 avg | 70.9 ns（92%<300ns） | 1056.9 ns（53%在 1-4µs） |
| 组首尾跨度 | 496 ns | ~5-7 µs |
| 主 walk 完成时刻 | 1168 ns > 跨度 | ~2100 ns << 跨度 |
| 8 个任务的去向 | 全部 PT MISS → 7 个被 dedup 挂起 | 后到者 PT 命中直通 |

每组分流核算（14544 组 × 8）：4.72 PT 命中 + 1.96 dedup 挂起 + 1.10 fresh walk + 0.24 hash 冲突 bypass ≈ 8 ✓。PT cache 8192 行（1024×8）< 14544 工作集页（1.78×）的替换损失把命中率压在 58.7%（理论上限 ~87.5%）。基线A 与任务2 的重复翻译分别被 dedup 和 PT cache 两个 catcher 接住，此消彼长。

### 12.5 PTW 主任务占数据任务比

- PTW 总任务（含预取）77357 / 116352 = 66.47%（skill 口径）

### 12.6 补充归因（对第 10 节的深化）

PT cache 接手重复翻译是任务2 平均 e2e 未恶化的关键缓冲：59% 数据任务免去 buffer 挂起（~1.9µs）改走 ~10ns 的 cache 查询。真正退化集中在 walk 路径（DDR 3.57→5.90 次、walk 延时 +49%、PTW 饱和 64/64），由 16 倍并发摊平后吞吐 −19.3%。

## 13. 追问分析：读写分离后为何读/写并发未同时顶满 320

**结论先行：读写分离确实生效（写满期间读并发不降反升）；读并发 171 不是被压制，而是 Little's Law L=λ×W 的自然结果——读侧供给被读口线速节拍限制在 λ≈129M/s，读任务驻留 W≈1.7µs，乘积只需 ~171，320 是上限不是目标。写侧 λ×W≈240 贴近上限才间歇顶满。**

### 13.1 分离生效的三重证据
1. **时间加权重构**（accept→release，与日志 CONC_WIN 逐位对齐 R 171.0/12.2%、W 239.5/36.7%）：写满 320 时段（36.7%）读并发 avg=**182.7 ≥ 全程 171**；
2. 读口带宽在写满时段（50~550µs 切片）保持 53.8~54.8 GB/s 平坦；读侧 580µs 先发完后写口带宽反升 49.7 GB/s；
3. 读写同时满仅 4.91%（=Global 640 顶满占比）；PARSER_CONC 快照中"弹 W 时读满"（OTHER_FULL 32207 次）并未阻塞写——写口门控只看 write_out/global。

### 13.2 读并发低的本质：λ 受线速、W 不够长
| | READ | WRITE |
|---|---|---|
| 任务数 | 72912 | 87088（含 CQ/MSI 29104 个写向小包） |
| 活跃跨度 | 566.5µs | 727.7µs |
| λ（到达率） | **128.8M/s（读口线速顶格 83.5%）** | 119.6M/s（被自家 320 门控反压） |
| W（accept→release 均值） | 1706.6ns | 2001.6ns（+295ns：写数据 e2e +500ns、每设备写保序 reorder 等待实证 1021.5ns、CQ/MSI 小包） |
| **L=λ×W** | **171.2 ✓（实测 171.0）** | **239.9 ✓（实测 239.5）** |

读持续顶满 320 需要 λ=187M/s（超读口 512B@64GB/s 线速上限 45%，物理不可能）或 W=2480ns（读路径慢 45%）。**读不满 = 注入线速顶格 + 服务够快，是健康状态**；瞬时触 320 仅 12.2% 时长（慢任务突发）。

### 13.3 写侧贴近上限的动态与自平衡
λ_write×W_write≈240（75% 上限），慢写突发成批驻留时冲上 320 → 写口门控 8762 次/233.7µs 反压 → λ 压到 119.6M/s → 写口带宽仅 64.5%（vs 读 83.9%，尽管写平均包 343.6B 更小、线速间隔仅 5.37ns、任务率潜力更高——恰证明写侧是额度受限而非线速受限）。读满时段 FIFO_r 积压任务被 parser 快速连弹（PARSER_CONC 读满快照占比 38.3% vs 时间占比 12.2%，~3 倍采样偏差），accept→pop 排队计入 W，构成"W 涨→L 涨→封顶→压 λ"的负反馈自平衡。

### 13.4 与 MPS128 场景对照
同为 SPLIT=1，MPS128（128B 小包→1ns 节拍，λ 可达 ~1000M/s）下读/写满额时长 81.5%/78.6%；本场景 512B 大包 λ 上限 ~154M/s，λ×W 天然 <320。**包长→线速节拍→λ 上限→λ×W 决定能否顶满**：分离消除的是跨向阻塞，不改变各方向自身的供给-驻留平衡。
