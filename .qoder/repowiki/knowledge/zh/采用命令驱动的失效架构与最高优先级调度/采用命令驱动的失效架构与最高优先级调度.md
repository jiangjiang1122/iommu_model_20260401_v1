# 采用命令驱动的失效架构与最高优先级调度

_来源：d05d581 → 1c79446 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
现有 SystemC 性能模型中 DC/PC/PT/Walker 四类 Cache 缺乏统一的失效处理机制，原有独立 invalidate_worker_thread 与调度进程并发访问同一 cache 阵列存在竞态问题，且 CQ 解析的命令未桥接到性能级失效通路。

## 决策驱动
- 消除并发竞态
- 符合 RISC-V IOMMU V1.0.1 spec
- 零热路径开销保护基线
- IOFENCE 语义正确性

## 备选方案
- **独立失效线程 + 轮询仲裁** _（已否决）_ — 优点：实现简单；缺点：与主调度进程并发访问导致竞态；无法保证失效优先级；IOFENCE 语义难以保证
- **统一 FIFO + 最高优先级调度** — 优点：消除竞态；失效任务优先执行；通过 join 计数保证 IOFENCE 语义；命令驱动零热路径开销

## 决策
在 iommu_top 新增 cq_process_thread 将 CQ 解析的 IODIR/IOTINVAL/IOFENCE 命令写入 cache_subsystem.invalidation_request_fifo，各 Cache 调度进程（dc_scheduler_thread、pt_hash_thread、walker_hash_thread）每轮先查失效 FIFO，命中则立即处理，否则按原策略处理常规任务。删除所有独立 *_invalidate_worker_thread，合并为单一调度器。

## 影响
消除了并发竞态问题，保证了失效指令的及时性和 IOFENCE 语义正确性。但需确保一条失效指令的全部子操作完成后才回响应，增加了 join 计数逻辑复杂度。
