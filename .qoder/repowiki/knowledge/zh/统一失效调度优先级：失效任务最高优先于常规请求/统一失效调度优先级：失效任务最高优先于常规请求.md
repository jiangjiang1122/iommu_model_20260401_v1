# 统一失效调度优先级：失效任务最高优先于常规请求

_来源：06028a2 → d05d581 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
原 DC/PT/Walker 各缓存有独立的 invalidate_worker_thread 与调度进程并发访问同一 cache 阵列，存在竞态问题；且失效命令与常规请求轮询平级导致失效延迟不可控。

## 决策驱动
- 消除多线程并发访问 cache 阵列的竞态
- 保证失效命令的低延迟处理
- 简化调度逻辑减少代码分支
- IOFENCE 语义依赖失效完成通知

## 备选方案
- **维持独立 invalidate_worker_thread** — 优点：与现有架构改动最小；缺点：与调度进程并发访问同一 cache 阵列产生竞态；调度逻辑分散
- **合并调度器 + 失效最高优先** — 优点：单一调度入口消除竞态；invalidate > request/update 的优先级确保失效及时完成；pt_hash/walker_hash 线程入口直接检查 pt_invalidate_fifo/walker_inval_fifo；缺点：需重构 dc_worker_thread/dc_update_worker_thread/dc_invalidate_worker_thread 为单一 dc_scheduler_thread
- **双队列分离（失效队列 + 请求队列）** — 优点：职责清晰；缺点：仍需仲裁逻辑；不如单队列内优先级切换简洁

## 决策
将 DC/PC/MSIPT 的多个 worker 线程合并为单一 scheduler_thread，PT/Walker 的 hash 线程入口新增 invalidate FIFO 检查（最高优先级，在乒乓仲裁之前）；PRECISE/SCAN_RANGE 按 ram_id 广播子任务到对应 RAM worker，SCAN/GLOBAL 广播全部 RAM 扫描本区间，通过 join 计数聚合 affected_entries 后回响应。

## 影响
消除了独立 invalidate_worker_thread 与调度进程的竞态；一条失效指令的全部子操作完成后才回响应（满足 IOFENCE 语义）；DC→PC 关联失效替代原 PT/Walker/MSI 级联，符合 spec V1.0.1 收敛设计；删除 pt_invalidate_worker_thread 并将逻辑并入 pt_hash_thread。
