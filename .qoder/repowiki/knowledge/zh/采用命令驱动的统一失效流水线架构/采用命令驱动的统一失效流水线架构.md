# 采用命令驱动的统一失效流水线架构

_来源：1c79446 → 1a81109 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
IOMMU 性能模型中 DC/PC/PT/Walker 四类 Cache 的失效处理分散在多个独立 worker 线程，存在并发访问竞态、调度优先级不明确、IOFENCE 语义难以保证等问题。需要统一接入 CQ 命令队列并建立一致的失效 pipeline。

## 决策驱动
- 消除多线程竞态
- 确保 IOFENCE 语义正确性
- 零热路径开销（基线保护）
- 符合 riscv-iommu V1.0.1 spec

## 备选方案
- **统一 FIFO + 最高优先级调度** — 优点：消除竞态、简化调度逻辑、IOFENCE 等待条件清晰、与现有 RAM worker 串行性兼容
- **保留独立 invalidate_worker_thread** _（已否决）_ — 优点：改动最小；缺点：与调度进程并发访问 cache 阵列导致竞态、无法保证失效优先于常规请求

## 决策
所有 Cache 的调度进程每轮先查 invalidation_request_fifo，命中则立即处理失效任务；删除独立的 *_invalidate_worker_thread，将失效逻辑并入 pt_hash_thread/walker_hash_thread/dc_scheduler_thread 等主调度入口，通过 join 计数保证一条指令全部子操作完成后才回响应。

## 影响
DC/PC/MSIPT 合并为单一调度线程；PT/Walker 的 pt_hash/walker_hash 线程中 invalidate 检查排在乒乓仲裁之前；新增 pending_inval_count_ 用于 IOFENCE.C 等待条件；原有独立 invalidate worker 被移除，减少线程间同步复杂度。
