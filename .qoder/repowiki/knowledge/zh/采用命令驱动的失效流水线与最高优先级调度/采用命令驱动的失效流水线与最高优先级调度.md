# 采用命令驱动的失效流水线与最高优先级调度

_来源：e917392 → a32da0e 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
原有 DC/PT/Walker Cache 的失效处理分散在独立 worker 线程中，与调度进程并发访问同一 cache 阵列存在竞态问题；同时失效任务与普通请求/更新任务平级轮询，无法保证失效语义（如 IOFENCE）的正确性。

## 决策驱动
- 消除并发竞态
- 严格遵循 spec 失效时序
- IOFENCE 语义正确性
- 零热路径开销

## 备选方案
- **统一失效 FIFO + 最高优先级调度** — 优点：消除竞态、确保失效优先、简化 join 计数、IOFENCE 等待条件清晰
- **保留独立 invalidate_worker_thread** _（已否决）_ — 优点：改动最小；缺点：与调度进程并发访问导致竞态、响应时序难以保证

## 决策
将 DC/PC/MSIPT 的多个 worker 合并为单一 scheduler_thread，PT/Walker 的 hash_thread 入口新增 pt_invalidate_fifo/walker_invalidate_fifo 检查且优先级最高；所有失效子操作通过 join 计数聚合后回响应，IOFENCE.C 扩展等待 pending_inval_count_==0。

## 影响
DC→PC 关联失效替代原 PT/Walker/MSI 级联（符合 spec V1.0.1）；各 Cache 的 RAM worker 串行性被复用以保证原子性；基线场景（5/6/7/8）不发失效命令时热路径仅一次 lib_count_==0 判断。
