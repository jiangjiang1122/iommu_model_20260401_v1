## 简介
本项目是一个基于 SystemC 的 RISC-V IOMMU 性能建模与仿真系统，提供地址转换、故障处理、设备上下文管理、多级缓存（DC/PC/PT/Walker/MSIPT）、去重与预取、两阶段翻译、MSI 路径、DDR 仲裁与带宽控制等能力。通过可配置的测试场景与丰富的统计指标，可用于评估不同负载下的吞吐、延迟、缓存命中率、并发度与瓶颈点。

## 项目结构
- 顶层入口：main.cpp 负责实例化 IOMMU、RP、PCIENOC、SLINK、DDR 模块并绑定 TLM 端口，启动仿真。
- IOMMU 顶层：iommu_top.* 实现流水线、缓存子系统集成、DDR 仲裁、重排序输出、统计监控、失效桥接等。
- 功能模型：iommu_fun_model.* 实现规范语义（ATC/ATS/中断/故障/两阶段翻译等）。
- 性能模型：iommu_perf_model.* 实现命令队列、页表走读（PTW）、重排序、转发器、MSIPT Cache、任务缓存转换、解析器等。
- 缓存子系统：cache_src/* 提供 DC/PC/PT/Walker/MSIPT/Dedup 缓存及多 RAM 并行、失效管线、统计收集。
- 外设与测试：rp/*、pcienoc/*、ddr/*、slink/* 提供 Root Port、NoC、DDR、链路等模型与多种测试线程。
- 构建与脚本：Makefile 支持多场景编译与运行；tmp/* 包含大量分析脚本与数据。

## 架构总览
IOMMU 接收来自 RP 的 AT 请求，经 Parser 分类后进入 Collector，查询 DC/PC 配置，再进入 PT Cache/Walker Cache 前置查询，必要时触发 PTW 进行页表走读，结合 Dedup Buffer 与预取机制减少重复 DDR 访问，最终由 Forwarder 输出响应或 Fault/CQ 处理。DDR 访问经 Arbiter 按优先级与带宽限制调度。

```mermaid
TOP->>CS : PT Cache 查询 / Walker 前置查询
alt PT HIT
CS-->>TOP : 直接命中
TOP->>OUT : 转发响应
else MISS
TOP->>PTW : 页表走读
PTW->>DDR : 页表读取
DDR-->>PTW : 数据返回
PTW-->>TOP : PTE 解析结果
TOP->>CS : 更新 PT Cache / Dedup Buffer
TOP->>OUT : 转发响应
end
OUT-->>RP : 响应 (END_RESP)
```

## 详细组件分析

### IOMMU 顶层 iommu_top
- 职责：
  - 接收 AT 请求，执行带宽控制与入队输入流水线延时线。
  - 配置与路由：根据 DC/PC 决定翻译阶段、MSI 分流、Walker 前置查询、PT Cache 查询。
  - 管理多个 FIFO 与 PEQ，协调各子模块（xDTW、PT Cache、PTW、MSIPTW、Forwarder、Fault/CQ）。
  - DDR 仲裁：统一调度 xDTW/PTW/MSIPTW/CTRL/MRIF 请求，维护 outstanding 计数与读写分离并发统计。
  - 重排序输出：写请求按 task_id 单调保序，读请求到达即输出。
  - 统计与监控：端到端延迟、端口间隔、PTW 并发、DDR 并发峰值、失效监控等。
- 关键流程：
  - 输入路径：axi_slave_nb_transport_fw -> input_delay_thread -> inbound_fifo -> parser_thread。
  - 配置与路由：configure_and_route -> walker_front_request_fifo -> pt_request_fifo。
  - DDR 响应：ddr_nb_transport_bw -> 按 source_module 分发到对应 rsp_ddr_fifo。
  - 输出路径：forwarder/fault -> reorder_output_thread -> send_response_to_initiator。

### 缓存子系统 CacheSubsystem
- 职责：
  - 统一管理 DC/PC/PT/Walker/MSIPT/Dedup 缓存，提供统一的请求/更新/失效通道。
  - 失效管线：支持全局、DDT/PDT、VMA/GVMA、范围扫描、延迟失效（LIB/VN）等。
  - 多 RAM 并行：PT/Walker/Dedup 采用 Hash + 多 RAM Worker + Join 模式，提升吞吐。
  - 统计报告：Scheduler 间隔、RAM 利用率、Hash 忙时、反压次数、预取丢弃等。
- 关键接口：
  - dc_request_fifo/pc_request_fifo/pt_request_fifo/walker_request_fifo/msi_request_fifo
  - dedup_request_fifo/dedup_update_fifo/dedup_inside_request_fifo
  - invalidation_request_fifo/invalidation_response_fifo
  - walker_front_request_fifo/walker_front_response_fifo

### 任务与上下文 iommu_task_t
- 职责：
  - 承载任务身份、地址类型、上下文（DC/PC/IOSATP/IOHGATP）、翻译结果（PA/GPA/页大小）、Walker 中间状态、预取组信息、MSI 标记等。

## 性能考量
- 带宽控制：
  - 入口端口按数据长度计算延迟，控制包固定延迟；DDR 端口按带宽公式计算延迟，维护 outstanding 计数与峰值统计。
- 并发与反压：
  - DDR 仲裁按优先级（CTRL > RR）调度，维护全局与读写分离 outstanding；FIFO 满时阻塞上游，避免丢包。
- 缓存与预取：
  - PT Cache 与 Walker Cache 前置查询减少 DDR 访问；Dedup Buffer 与预取组降低重复 walk；多 RAM 并行提升吞吐。
- 统计与监控：
  - 端到端延迟、端口间隔、PTW 并发、DDR 并发峰值、失效监控、Scheduler 间隔、RAM 利用率、Hash 忙时、反压次数等。

## 故障排查指南
- 常见问题：
  - DDR 响应队列为空：检查 pending 队列与 outstanding 计数，确认请求已正确入队。
  - FIFO 阻塞：检查深度与消费速率，调整反压策略或优化下游处理。
  - 失效未生效：确认失效管线启用与 NL/S 扩展位配置，检查 LIB 容量与 VN 回绕。
- 调试建议：
  - 启用 DEBUG 宏，打印关键路径日志（如 axi_slave_nb_transport_fw、ddr_nb_transport_bw、configure_and_route）。
  - 使用 Makefile 的 TEST 选项切换不同场景，逐步缩小问题范围。
  - 利用 tmp/* 中的分析脚本提取统计与分布，定位瓶颈。
