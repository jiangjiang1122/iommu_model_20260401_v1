## 简介
本技术文档面向IOMMU性能参数配置系统，系统性阐述性能参数的分类、作用机制与配置方式，覆盖缓存参数、流水线参数、系统参数、DDR与端口带宽参数、SLINK NoC延迟参数、IO_PACKET_BYTES包大小参数、以及去重与预取相关参数。**最新更新重点修复了C=8配置下的环形等待死锁问题，通过将TEST_CFG_PT_UPDATE_FIFO_DEPTH从32增加到1024，解决了8盘8通道和16盘8通道场景下的系统停摆问题。** 同时新增了多个性能参数配置选项，包括去重延迟更新、严格512B门控、SLINK NoC延迟可调等特性。文档同时给出参数配置文件的格式与语法、参数调优指南与最佳实践、不同工作负载下的优化策略、参数变更对系统性能的影响评估方法，以及参数配置的自动化工具与验证方法。

**最新优化**：新增了基于预留的去重缓存准入控制机制（`TEST_CFG_DEDUP_ADMISSION_CTRL`），通过reservation-based buffer management防止溢出并提供反压信号，性能测试显示启用准入控制后吞吐量提升50.1%。**特别重要的是新增了IO_PACKET_BYTES参数支持，通过`TEST_CFG_IO_PACKET_BYTES`宏支持从默认512B到任意值的动态配置，为理论峰值IOPS计算提供了精确的工具，同时保持了时序中性特性。** 同时，多通道测试框架的引入使得可以在单设备环境下模拟高并发场景，支持最多16个通道的并行处理，显著提升了测试的灵活性和效率。**最重要的是，系统现在支持强大的多设备×多通道测试架构，通过`TEST_CFG_MULTIDEV_MC_SCENE`启用的N个设备×C个通道的二维并发测试场景，配合读写端口分离机制和可配置的内存控制器队列深度，为复杂负载场景提供了完整的测试解决方案。**

## 核心组件
- 性能参数头文件：集中定义FIFO深度、缓存参数、AXI/DDR参数、SLINK NoC延迟参数、IO_PACKET_BYTES包大小参数、并发限制、处理延迟、系统参数等，是性能建模与仿真控制的核心依据。
- 缓存配置文件：以JSON描述全局时钟周期、随机种子、各缓存子系统的集合数、路数、替换策略及统计输出选项；支持从文件或字符串解析。
- **缓存基础架构**：CacheBase模板类提供统一的缓存操作接口，包含查找、填充、失效等核心功能，并通过read_set_latency_cycles参数控制缓存访问延迟。
- **设备上下文缓存(DCCache)**：专门用于缓存设备上下文信息，经过优化的read_set_latency_cycles=0配置实现了零延迟的设备上下文访问。
- 解析器线程：负责入站任务的接收、全局outstanding反压、任务分类与属性提取、模式检查、分发至Collector与缓存查询队列。
- 任务与上下文：统一的任务结构体承载设备/进程上下文、翻译结果、流水线状态、去重与预取相关字段，支撑性能统计与流水线控制。
- 去重与预取参数：定义去重Buffer容量、反压策略、PT Cache占位位、默认预取深度、Burst读取限制等。
- **去重缓存子系统**：实现了基于预留的准入控制机制，通过`TEST_CFG_DEDUP_ADMISSION_CTRL`参数控制，提供reservation-based buffer management防止溢出和反压信号。
- **IO_PACKET_BYTES包大小参数**：定义了可配置的包大小（默认512B），用于理论峰值IOPS计算，不影响实际时序行为。
- **SLINK NoC模块**：模拟IOMMU与DDR之间的NoC互连路径，使用PEQ管道延迟在请求和响应路径上实现可配置的延迟。
- **多通道测试框架**：支持单设备内多通道并发测试，通过轮询仲裁和统一输出口注入请求。
- **多设备×多通道测试架构**：支持N个设备×C个通道的二维并发测试场景，通过`TEST_CFG_MULTIDEV_MC_SCENE`启用，提供完整的设备级和通道级并发控制。
- **读写端口分离机制**：通过`TEST_CFG_SPLIT_RW_PORTS`标志启用独立的读/写端口和发送进程，提升并发性能和资源利用率。
- **内存控制器队列深度优化**：通过`TEST_CFG_MC_RW_QUEUE_DEPTH`参数提供近乎无界的读写发送队列深度（默认65536）。
- **多设备架构支持**：通过 `iommu_md::MAX_DEVICE_COUNT` 定义最大设备数为16，支持多设备并发处理和每设备独立的写保序队列。
- **写保序队列增强**：支持全局单一写保序队列和每设备独立写保序队列两种模式，后者通过 `TEST_CFG_PERDEV_WRITE_ORDER` 标志启用。
- DDR内存模块：模拟DDR存储器，提供TLM接口，支持AT模式和阻塞传输模式。
- **编译时参数配置**：通过Makefile的TEST_FLAGS支持动态配置端口宽度、全局未完成请求数、PT去重缓冲区大小、PTW未完成任务、SLINK NoC延迟和IO_PACKET_BYTES包大小，提供灵活的参数调优能力。
- Walker Cache实现：三级子表结构（PTWc_1、PTWc_2、PTWc_3），支持页表遍历中间结果缓存，提供查找和更新接口。
- **场景13混合负载测试**：针对4KB随机读写+SQ/CQ/MSI混合工作负载的专用测试场景，支持高并发和对称读写配置。

## 架构总览
IOMMU性能参数配置系统通过"参数定义文件 + 缓存配置文件 + 缓存基础架构 + 解析器线程 + 任务上下文 + 去重缓存子系统 + SLINK NoC模块 + IO_PACKET_BYTES包大小参数 + 多通道测试框架 + 多设备×多通道测试架构 + 读写端口分离机制 + 多设备架构支持 + DDR内存模块 + 编译时参数配置 + Walker Cache"的组合实现：
- 参数定义文件提供静态参数，驱动FIFO深度、缓存规模、SLINK NoC延迟、IO_PACKET_BYTES包大小、并发上限、处理延迟等。
- 缓存配置文件提供运行期可调整的缓存结构参数与统计选项，经解析器加载后参与仿真。
- **缓存基础架构**：CacheBase模板类提供统一的缓存操作接口，通过read_set_latency_cycles参数精确控制缓存访问延迟。
- **设备上下文缓存优化**：DCCache采用read_set_latency_cycles=0的配置，实现了零延迟的设备上下文访问，显著提升性能。
- **去重缓存子系统**：实现了基于预留的准入控制机制，通过`dedup_admission_ok()`函数检查缓冲区可用性，在Buffer满时跳过request出队形成反压，保证释放路径畅通避免死锁。
- **IO_PACKET_BYTES包大小参数**：定义了可配置的包大小（默认512B），用于理论峰值IOPS计算，公式为`theory_iops = AXI_SLAVE_0_BANDWIDTH_MBPS / 8 / IO_PACKET_BYTES`，不影响实际时序行为。
- **SLINK NoC模块**：模拟IOMMU与DDR之间的NoC互连路径，通过PEQ管道延迟实现可配置的延迟，支持从默认50ns到任意值的动态配置。
- **多通道测试框架**：支持单设备内多通道并发测试，通过轮询仲裁和统一输出口注入请求，复用多设备追踪功能。
- **多设备×多通道测试架构**：通过`TEST_CFG_MULTIDEV_MC_SCENE`启用的N个设备×C个通道的二维并发测试场景，提供完整的设备级和通道级并发控制，支持最多16×16=256条独立注入流。
- **读写端口分离机制**：通过`TEST_CFG_SPLIT_RW_PORTS`标志启用独立的读/写端口和发送进程，通过`TEST_CFG_MC_RW_QUEUE_DEPTH`参数提供近乎无界的读写发送队列深度（默认65536），显著提升并发性能。
- **多设备架构支持**：通过 `iommu_md::MAX_DEVICE_COUNT` 定义最大设备数为16，支持每设备独立的写保序队列，设备间写操作互不阻塞。

## PT更新FIFO深度优化

### PT更新FIFO深度变更概述
**重要更新**：将`TEST_CFG_PT_UPDATE_FIFO_DEPTH`从32增加到1024，解决了C=8配置（8盘8通道和16盘8通道）下的环形等待死锁问题。这是一个关键的稳定性修复，确保系统在高压负载下能够正常运行。

### 死锁根因分析
**环形等待环路**：
```
Buffer满(320) -> 准入关闭 -> dedup_request_fifo满(64) -> 
pt_ram_worker阻塞于push_fifo(dedup_request_fifo) -> 
pt_ram_fifo满(8) -> pt_hash_thread阻塞 -> 
pt_update_fifo满(32) -> agg_flush阻塞于write() -> 
无法生产dedup_update -> Buffer永不释放 -> 死锁
```

**关键发现**：
- `pt_update_fifo`是环上唯一的充分边（binding edge）
- 旧注释声称"默认32与历史场景逐位一致"是错误的
- 健康场景下`pt_update_fifo`峰值已达32/32=100%，说明环一直在贴满载运行
- 当并发开页数继续上升时，环即闭合导致死锁

### 解决方案设计原理
**为什么选择1024**：
- 回填消息数上界为"在途组数 × 每组iova数"
- 在途任务总数受`IOMMU_GLOBAL_MAX_OUTSTANDING`(640)约束
- 与同文件`FIFO_DEPTH_PT_CACHE_TO_FWD=1024`同源，需容纳全部在途任务
- 取1024使agg_flush的回填写入在物理上不可能被顶住

**治标而非治本**：
- 扩容属于"治标"方案，靠"余量不可耗尽"避免闭环
- 环形依赖本身仍然存在
- 治本需要解开环上那条唯一的充分边：pt_ram_worker向dedup_request_fifo的阻塞写
- 或让agg_flush的回填写入改为非阻塞+spill

### 实测验证结果
**C=8场景测试结果**：
- 8盘8通道：PASS，稳态IOPS ALL=255.963 Mreq/s
- 主占位创建/释放 = 2319/2319（完全对账，零孤儿）
- Admission stall = 555次/4817.3ns（准入控制在正常降速，而非死锁）
- 系统退化为"准入控制拦一下放一行"的正常降速

**副作用说明**：
- 本值参与时序，改动后所有场景的绝对吞吐都会漂移
- 历史基线不再逐位可复现
- 如需复现旧基线，显式传`-DTEST_CFG_PT_UPDATE_FIFO_DEPTH=32`即可

## IO_PACKET_BYTES包大小参数化

### IO_PACKET_BYTES参数概述
IO_PACKET_BYTES参数是IOMMU性能参数配置系统中新增的可配置包大小参数，用于理论峰值IOPS计算。该参数通过`TEST_CFG_IO_PACKET_BYTES`宏实现，默认值为512B，支持从命令行动态配置不同的包大小场景。

### 参数设计原理
**核心特性**：
- **时序中性**：参数仅用于理论峰值IOPS计算，不影响实际的仿真时序行为
- **带宽计算**：理论峰值IOPS = AXI_SLAVE_0_BANDWIDTH_MBPS / 8 / IO_PACKET_BYTES
- **历史兼容**：默认512B保持与历史口径一致（4KB切成8x512B）
- **小包场景**：支持128B小包场景，使128GB/s下理论峰值从250 M/s提升至1000 M/s

**计算公式**：
```
theory_iops = AXI_SLAVE_0_BANDWIDTH_MBPS / 8.0 / IO_PACKET_BYTES
```

其中：
- AXI_SLAVE_0_BANDWIDTH_MBPS：AXI端口带宽（Mbps）
- IO_PACKET_BYTES：包大小（字节）
- theory_iops：理论峰值IOPS（M trans/s）

## SLINK NoC延迟参数化

### SLINK NoC模块概述
SLINK模块模拟IOMMU与DDR之间的NoC互连路径，专门用于页表/目录表访问。该模块使用PEQ管道延迟在请求和响应路径上实现可配置的延迟，通过`TEST_CFG_SLINK_NOC_LATENCY_NS`宏支持从默认50ns到任意值的动态配置。

### SLINK延迟参数配置
- **默认延迟**：50ns（低延时场景）
- **可配置范围**：通过`TEST_CFG_SLINK_NOC_LATENCY_NS`宏从命令行覆盖
- **延迟计算**：一次DDR页表访问延时 = 前向SLINK + DDR_INTERNAL_LATENCY_NS(100) + 回程SLINK
- **默认合计**：50+100+50=200ns
- **配置示例**：设置100ns则合计300ns(100+100+100)，用于观测页表访问延时对整体性能的影响

### SLINK模块实现细节
**核心特性**：
- **双向延迟**：请求路径和响应路径都使用相同的PEQ延迟
- **FIFO缓冲**：请求FIFO和响应FIFO深度均为256，匹配IOMMU master outstanding
- **TLM接口**：支持nb_transport_fw和nb_transport_bw回调
- **线程处理**：四个独立线程分别处理请求转发、响应转发和对应的输出处理

## 多设备×多通道测试架构

### 多设备×多通道测试架构概述
多设备×多通道测试架构是IOMMU性能参数配置系统中最复杂的测试场景，通过在场景13-v4多设备(N)基线之上，将"每设备1条顺序流"扩展为"每设备内部C条并发通道"，共S=N*C条独立注入流。该架构支持最多16×16=256条独立注入流的二维并发测试。

### 核心架构设计
**关键设计原则**：
- **二维轮询调度**：通过"通道外层/设备内层"的2D逐包轮询(i = c*N + d)交错注入
- **全局唯一页分配**：N*GROUPS个4KB页两两不重复(跨设备跨通道)，确保测试数据的独立性
- **固定负载模式**：每设备总量GROUPS组，拆分到C个通道，每设备包数=GROUPS*11+1=10000
- **设备级统计聚合**：复用多设备追踪(md_trace)，按设备(did=0..N-1)聚合统计

**架构组成**：
- **S个producer进程**：各自把本流Request压入自有有界队列(反压)，不调用入口
- **1个RR scheduler**：唯一nb_transport_fw调用者，逐包轮询(每次取1个Request)
- **1个watchdog**：沿用多设备超时诊断
- **设备级共享状态**：Device结构体包含设备上下文、VS映射、MSI、控制包等共享资源
- **流级独立状态**：Stream结构体包含独立的随机页子集、就绪队列、统计信息等

### 读写端口分离机制概述

- **带宽提升**：每个端口512bit@1000MHz = 64GB/s，双端口合计128GB/s

### 编译时参数概述
IOMMU性能参数配置系统新增了增强的编译时参数配置功能，允许通过Makefile的TEST_FLAGS标志动态控制端口宽度（1024位AXI）、全局未完成请求数、PT去重缓冲区大小、PTW未完成任务、SLINK NoC延迟和IO_PACKET_BYTES包大小。这一功能提供了更灵活的参数调优能力，无需修改源代码即可调整关键性能参数。

- **TEST_CFG_AXI_PORT_WIDTH**：控制AXI端口宽度配置

### 去重缓存准入控制机制详解

#### 准入控制原理
新增的`TEST_CFG_DEDUP_ADMISSION_CTRL`参数实现了基于预留的去重缓存准入控制机制：

**核心机制**：
- **预留计数**：scheduler从request_fifo出队时增加`dedup_reserved_count_`（预占1个未来Buffer槽）
- **准入检查**：通过`dedup_admission_ok()`函数检查`valid + reserved < PT_DEDUP_BUFFER_SIZE`
- **原子性保证**：在SystemC协作式调度下，检查与后续reserved++之间无wait，天然原子
- **反压机制**：Buffer满时跳过request出队，任务滞留dedup_request_fifo形成反压

**工作流程**：
```mermaid
flowchart TD
A["Request到达Scheduler"] --> B{"检查dedup_admission_ok()"}
B --> |可用| C["出队request并增加reserved_count_"]
B --> |不可用| D["跳过本轮request，继续服务inside/update"]
C --> E["Worker处理request"]
E --> F{"allocate_entry成功?"}
F --> |成功| G["reserved_count_-- (reserved->valid)"]
F --> |失败| H["等待free_event (理论上不应发生)"]
G --> I["正常处理流程"]
D --> J["组合事件等待: free_event | 三FIFO写入"]
J --> K["继续调度循环"]
```

## 性能考量
- FIFO深度与并发限制：FIFO过小导致阻塞，过大增加存储与延迟；outstanding上限需平衡吞吐与内存占用。
- **缓存延迟优化**：DC缓存read_set_latency_cycles优化至0周期，显著减少设备上下文访问延迟；PC缓存保持1周期，平衡性能与资源使用。
- **SLINK NoC延迟优化**：通过`TEST_CFG_SLINK_NOC_LATENCY_NS`参数可动态调节NoC延迟，默认50ns，支持从低延迟到高延迟的各种场景测试。
- **IO_PACKET_BYTES包大小优化**：通过`TEST_CFG_IO_PACKET_BYTES`参数可动态调节包大小，默认512B，支持理论峰值IOPS计算而不影响实际时序行为。
- **PT_UPDATE_FIFO_DEPTH优化**：通过`TEST_CFG_PT_UPDATE_FIFO_DEPTH`参数可动态调节PT更新FIFO深度，默认1024，解决C=8配置下的死锁问题。
- 缓存规模与替换策略：增大Size/Assoc提升命中率，但增加访问延迟；替换策略影响抖动与命中率。
- AXI带宽与DDR延迟：带宽不足导致端口饱和，延迟过高放大尾延迟；需结合任务特征与NoC拓扑设定。
- 处理延迟：各模块延迟叠加决定端到端时延，应优先优化瓶颈模块。
- 去重与预取：合理设置去重Buffer与预取深度，可显著降低重复访问与DDR压力，但需避免过度预取造成带宽浪费。
- **编译时参数优化**：通过编译时参数可以快速调整端口宽度、全局未完成请求数、PT去重缓冲区大小、PTW未完成任务、SLINK NoC延迟、IO_PACKET_BYTES包大小和PT_UPDATE_FIFO_DEPTH，针对不同工作负载获得最佳性能。
- **去重缓存准入控制**：启用`TEST_CFG_DEDUP_ADMISSION_CTRL`后可通过reservation-based buffer management防止溢出，提供反压信号，吞吐量提升50.1%。
- **多通道测试性能**：多通道测试框架支持单设备内高并发场景，通过轮询仲裁和统一输出口注入，有效模拟真实负载。
- **多设备×多通道测试性能**：N个设备×C个通道的二维并发测试场景，支持最多256条独立注入流，提供完整的设备级和通道级并发控制。
- **读写端口分离性能**：通过独立的读/写端口和发送进程，显著提升并发性能和资源利用率，支持更高的吞吐量和更低的延迟。
- **内存控制器队列深度优化**：通过`TEST_CFG_MC_RW_QUEUE_DEPTH=65536`提供近乎无界的读写发送队列深度，避免队列拥塞导致的性能瓶颈。
- **多设备架构性能**：每设备写保序队列消除了设备间写操作阻塞，显著提升多设备场景下的整体性能。
- Walker Cache性能：三级缓存结构可显著减少页表遍历的DDR访问次数，在重复访问场景下可获得显著加速效果。
- **设备上下文缓存优势**：零延迟的设备上下文访问消除了IOMMU启动和上下文切换的性能瓶颈，特别适合高并发虚拟化场景。
- **场景13性能优势**：对称读写配置和高并发PTW处理显著提升了混合负载下的整体性能，特别是在高带宽场景下表现优异。
- **理论峰值IOPS准确性**：IO_PACKET_BYTES参数确保了理论峰值IOPS计算的准确性，便于在不同包大小场景下进行公平的性能对比。

## 故障排查指南
- 入站阻塞：若解析器持续等待outstanding释放事件，检查全局outstanding上限与重排序输出速率。
- 缓存抖动：命中率不稳定可能源于替换策略或并发冲突，可通过增大Assoc或调整替换策略缓解。
- DDR拥塞：观察DDR请求/响应FIFO深度与outstanding，适当提高AXI master并发上限或优化预取策略。
- 预取异常：确认预取深度与Burst限制，避免跨页表边界与过多未完成请求。
- **缓存延迟问题**：如果DC缓存性能异常，检查read_set_latency_cycles配置是否正确设置为0，确认缓存配置解析正常。
- **设备上下文缓存问题**：验证DCCache的查找操作是否正确使用零延迟配置，检查设备上下文数据的正确性。
- **SLINK延迟问题**：如果SLINK延迟配置不正确，检查`TEST_CFG_SLINK_NOC_LATENCY_NS`参数设置，确认延迟值符合预期。
- **IO_PACKET_BYTES配置问题**：如果理论峰值IOPS计算异常，检查`TEST_CFG_IO_PACKET_BYTES`参数设置，确认包大小值符合预期。
- **PT_UPDATE_FIFO_DEPTH配置问题**：如果出现C=8配置下的死锁，检查`TEST_CFG_PT_UPDATE_FIFO_DEPTH`参数设置，确认值是否为1024。
- **多通道测试问题**：如果多通道测试出现异常，检查`TEST_CFG_MULTI_CHANNEL_SCENE`和相关通道配置参数，确认通道数量和队列深度设置合理。
- **多设备×多通道测试问题**：如果多设备×多通道测试出现异常，检查`TEST_CFG_MULTIDEV_MC_SCENE`、`TEST_CFG_NUM_DEVICES`、`TEST_CFG_MD_CHAN_PER_DEV`等参数，确认设备数量和通道数量配置合理。
- **读写端口分离问题**：如果读写端口分离机制出现异常，检查`TEST_CFG_SPLIT_RW_PORTS`和`TEST_CFG_MC_RW_QUEUE_DEPTH`参数，确认读写队列深度和分离机制配置正确。
- **编译时参数问题**：若编译时参数未生效，检查Makefile中的TEST_FLAGS配置，确认编译器正确接收了-D参数。
- **去重缓存准入控制问题**：如果启用`TEST_CFG_DEDUP_ADMISSION_CTRL`后出现性能下降，检查`dedup_admission_wait_cnt_`和`dedup_request_fifo_peak_`统计，确认反压机制正常工作。
- **多设备架构问题**：如果多设备场景出现异常，检查 `TEST_CFG_MULTI_DEVICE_SCENE` 和 `TEST_CFG_PERDEV_WRITE_ORDER` 配置，确认设备数量和队列深度设置合理。
- **写保序队列问题**：如果写请求保序异常，检查 `reorder_write_order_dev` 数组配置和设备ID范围，确认每设备队列正常工作。
- Walker Cache问题：检查配置文件中的walker_cache.enabled设置，验证三级子表的配置参数，确认PTW模块的查找和更新接口正常工作。
- 构建脚本问题：确保build_cpp.sh具有执行权限，检查依赖库是否正确安装。
- **端口带宽问题**：如果AXI端口宽度配置不当，可能导致带宽不足或资源浪费，需要根据实际带宽需求调整TEST_CFG_AXI_PORT_WIDTH参数。
- **场景13配置问题**：如果场景13性能异常，检查SCENE13_PTW、SCENE13_BUFFER和读写分离配置是否正确，确认全局并发设置与硬件资源匹配。
- **MPS/MRRS小包场景问题**：如果小包场景测试异常，检查MULTICHAN_MPS参数设置，确认128B小包场景的构建和配置正确。
- **多设备×多通道测试构建问题**：如果使用build_mdmc_rwsplit.sh或build_mdmc_nosplit.sh脚本构建失败，检查MULTIDEV_MC_SPLIT_RW参数设置，确认读写端口分离模式配置正确。

## 结论
IOMMU性能参数配置系统通过参数定义文件与缓存配置文件实现对仿真行为的精细控制。结合解析器线程与任务上下文，系统能够在不同工作负载下实现高并发、低延迟与大容量的平衡。**最新的重大优化包括：DC缓存的read_set_latency_cycles参数已优化至0个周期，显著减少了设备上下文缓存访问延迟，提升了整体IOMMU性能，同时保持了数据完整性和一致性保证。PC缓存的read_set_latency_cycles保持在1个周期，实现了性能与资源的平衡。** 新增的Walker Cache功能提供了三级页表缓存，可在重复访问场景下显著提升性能。**特别重要的新增功能是去重缓存准入控制机制（`TEST_CFG_DEDUP_ADMISSION_CTRL`），通过reservation-based buffer management防止溢出并提供反压信号，性能测试显示吞吐量提升50.1%。** 

**最重要的是，系统现在支持强大的IO_PACKET_BYTES包大小参数化功能，通过`TEST_CFG_IO_PACKET_BYTES`宏实现了从默认512B到任意值的动态配置，为理论峰值IOPS计算提供了精确的工具，同时保持了时序中性特性。** 同时，多通道测试框架的引入使得可以在单设备环境下模拟高并发场景，支持最多16个通道的并行处理，显著提升了测试的灵活性和效率。**此外，系统还支持强大的多设备×多通道测试架构，通过`TEST_CFG_MULTIDEV_MC_SCENE`启用的N个设备×C个通道的二维并发测试场景，配合读写端口分离机制（`TEST_CFG_SPLIT_RW_PORTS`）和可配置的内存控制器队列深度（`TEST_CFG_MC_RW_QUEUE_DEPTH=65536`），为复杂负载场景提供了完整的测试解决方案。** 

**最关键的改进是修复了C=8配置下的环形等待死锁问题，通过将`TEST_CFG_PT_UPDATE_FIFO_DEPTH`从32增加到1024，彻底解决了8盘8通道和16盘8通道场景下的系统停摆问题。** 这个修复虽然属于"治标"方案，但通过确保`pt_update_fifo`有足够的余量来避免闭环，使系统退化为正常的准入控制降速机制。同时新增了多个性能参数配置选项，包括去重延迟更新、严格512B门控、SLINK NoC延迟可调等特性，为不同工作负载提供了更精细的调优能力。建议以实际测试数据为依据，逐步调优FIFO深度、缓存规模、并发限制、SLINK NoC延迟、IO_PACKET_BYTES包大小、PT_UPDATE_FIFO_DEPTH和去重/预取策略，并利用新的编译时参数配置功能快速验证不同配置组合的性能表现，建立稳定的评估方法与自动化验证流程。

- 低延迟场景：减小FIFO深度与处理延迟，优化缓存替换策略，减少不必要的预取，确保端口带宽充足。
- 大容量场景：扩大缓存容量与Buffer容量，启用去重与预取，合理设置Burst读取限制，避免跨页表边界带来的额外开销。
- **缓存延迟调优**：对于高频访问的设备上下文，考虑将read_set_latency_cycles优化至0；对于中等访问频率的进程上下文，保持1周期延迟；对于低频访问的页表缓存，可适当增加延迟以减少资源消耗。
- **SLINK延迟调优**：根据实际NoC拓扑和DDR延迟特性，通过`TEST_CFG_SLINK_NOC_LATENCY_NS`参数调节延迟，默认50ns适用于低延迟场景，可根据需要增加到100ns或更高值进行对比测试。
- **IO_PACKET_BYTES包大小调优**：根据实际PCIe MPS/MRRS配置选择合适的包大小，默认512B适用于标准场景，128B适用于小包场景，通过理论峰值IOPS计算评估不同包大小的性能影响。
- **PT_UPDATE_FIFO_DEPTH调优**：在C=8配置下必须使用1024以避免死锁，其他场景可根据实际负载特征调整，默认1024提供足够的安全余量。
- **多通道测试调优**：在多通道场景下，通过`MULTICHAN_N`参数调节通道数量，通过`MULTICHAN_QUEUE_DEPTH`参数调节队列深度，通过`MULTICHAN_LOAD_MODE`参数选择合适的负载模式。
- **多设备×多通道测试调优**：在多设备×多通道场景下，通过`MULTIDEV_MC_N`参数调节设备数量，通过`MULTIDEV_MC_CHAN`参数调节每设备通道数，通过`MULTIDEV_MC_SPLIT_RW`参数启用读写端口分离，通过`MULTIDEV_MC_RWQ_DEPTH`参数调节读写队列深度。
- **读写端口分离调优**：在高负载场景下建议启用`TEST_CFG_SPLIT_RW_PORTS=1`以获得更好的并发性能，通过`TEST_CFG_MC_RW_QUEUE_DEPTH`参数调节读写队列深度，监控`rw_peak_r`和`rw_peak_w`指标评估队列使用情况。
- **去重缓存准入控制调优**：在高负载场景下建议启用`TEST_CFG_DEDUP_ADMISSION_CTRL=1`以获得更好的吞吐量和稳定性，监控`dedup_admission_wait_cnt_`和`dedup_request_fifo_peak_`指标评估反压效果。
- **多设备架构调优**：在多设备场景下建议启用 `TEST_CFG_PERDEV_WRITE_ORDER=1` 以获得更好的设备间并行性能，监控每设备的队列深度和HOL阻塞情况。
- Walker Cache调优：根据工作负载特征调整三级缓存的大小和相联度，重复访问场景下建议启用Walker Cache以获得最佳性能。
- **场景13调优**：针对混合负载场景，建议保持读写对称配置，根据实际负载比例微调读写并发比例，充分利用高带宽和低延迟优势。
- **KB4_GATE_STRICT_512调优**：如果需要统一real8回放与合成场景的4KB页并发统计口径，启用此参数确保统计一致性。
- **去重延迟更新调优**：在MPS/MRRS=128B小包场景下建议启用`TEST_CFG_DEDUP_DELAYED_UPDATE=1`以优化去重Cache更新性能。

### 不同工作负载下的优化策略
- 高并发：提升PTW/MSIPTW outstanding上限，增大PT Cache Assoc与Size，启用去重与预取，优化DDR带宽与延迟。
- 低延迟：降低Parser/Collector/Cache命中延迟，缩短FIFO深度，减少重排序输出延迟，优化NoC路径。
- 大容量：增大全局outstanding上限，扩展缓存容量，启用去重与预取，合理设置Burst读取与预取深度。
- **缓存优化策略**：针对虚拟化高并发场景，充分利用DC缓存的零延迟优势；对于混合访问模式，合理配置PC缓存的1周期延迟；对于页表密集型工作负载，优化PT缓存配置。
- **SLINK延迟优化策略**：对于低延迟要求的场景，保持默认的50ns延迟；对于高延迟环境模拟，可增加到100ns或更高；通过对比不同延迟值下的性能表现，找到最优配置点。
- **IO_PACKET_BYTES优化策略**：对于标准PCIe场景，使用默认的512B包大小；对于小包场景（MPS/MRRS=128），使用128B包大小；通过理论峰值IOPS计算评估不同包大小的性能影响。
- **PT_UPDATE_FIFO_DEPTH优化策略**：在C=8配置下必须使用1024以确保系统稳定性；在其他场景下可根据实际负载特征调整，但建议保持1024以提供足够的安全余量。
- **多通道优化策略**：在高并发场景下启用多通道测试，通过轮询仲裁和统一输出口注入，有效模拟真实负载；监控各通道的负载均衡和队列深度情况。
- **多设备×多通道优化策略**：在复杂负载场景下启用多设备×多通道测试，通过二维轮询调度模拟真实的多设备多通道并发场景；监控设备间和通道间的负载均衡情况。
- **读写端口分离优化策略**：在高负载场景下启用读写端口分离，通过独立的读/写端口和发送进程提升并发性能；监控读写队列的深度和峰值使用情况。
- **去重缓存优化策略**：在高负载场景下启用准入控制机制，通过预留机制避免Buffer溢出，提供更好的流量控制和反压机制。
- **多设备优化策略**：在多设备场景下启用每设备写保序队列，通过设备间并行处理提升整体吞吐量，监控设备间的负载均衡和HOL阻塞情况。
- Walker Cache优化：重复访问场景下启用Walker Cache，顺序扫描场景下可考虑降低预取深度，随机访问场景下谨慎启用以避免缓存污染。
- **场景13优化策略**：充分利用高并发PTW处理能力，保持读写对称配置以简化负载均衡，合理设置缓冲区大小以平衡内存使用和去重效果，启用准入控制机制提升吞吐量。
- **KB4_GATE_STRICT_512优化策略**：在需要统一统计口径的场景下启用此参数，确保real8回放与合成场景的4KB页并发统计一致性。
- **去重延迟更新优化策略**：在MPS/MRRS=128B小包场景下启用延迟更新机制，优化去重Cache的占位清除时机，避免重复派发PTW。
