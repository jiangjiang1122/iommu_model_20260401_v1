## 架构总览
缓存子系统通过SystemC sc_fifo连接各缓存模块，每个缓存拥有独立的请求/响应通道，避免串行化瓶颈。顶层CacheSubsystem维护以下关键流程：
- 查找流水线：请求进入对应缓存的请求FIFO，工作线程执行lookup，命中则返回响应，miss则触发后续处理。
- 填充流水线：外部模块发起update，缓存执行fill，必要时触发替换。
- 失效流水线：支持精确失效、扫描失效与全局失效；DC/PC失效后可级联触发PT/Walker/MSIPT失效。
- 统计与报告：StatsCollector记录访问、命中、miss、evict、invalidation、预取命中等，并生成摘要与直方图。

### DC Cache（设备上下文缓存）
- 功能：缓存设备ID到设备上下文（device_context_t）的映射，支持按设备ID查找与填充，支持DDT失效并返回受影响的gscid/pscid用于级联。

- 一致性：DDT失效后，返回受影响的上下文对，供上层触发PC/PT/Walker/MSIPT级联失效。
- 时延与统计：继承自CacheBase，包含仲裁、哈希、读set、比较、写way等时延建模与命中/miss统计。

### Walker Cache（页表遍历缓存）

**更新** WalkerCache经过重大改进，实现了三重缓存查询、仲裁机制和缓存污染预防等新特性。

- 功能：内含三个子表（PTWc_1/2/3），分别缓存不同层级页表中间结果，支持按VA/PA、阶段、SV48/X4模式查询与更新，支持按gscid/pscid/VMA/GVMA失效。
- 结构：PTWc_1为直接映射（1-way），PTWc_2为2-way组相联，PTWc_3为4-way组相联；支持sv39模式切换。
- 查询策略：**新增** lookup不指定level，内部按3>2>1顺序查询，命中level回传；update支持批量更新多个子表。
- 一致性：支持精确/扫描/全局失效，按gscid/pscid批量失效，以及与VMA/GVMA关联失效。
- **新增** 缓存污染预防：在update_entry中增加无效数据检查，防止将无效的中间结果写入缓存。

#### WalkerCache子表结构与哈希函数

WalkerCache的三个子表具有不同的配置和用途：

- **PTWc_1（第一级）**：1-way直接映射，缓存VPN[3]级别的中间结果，仅在SV48模式下启用
- **PTWc_2（第二级）**：2-way组相联，缓存VPN[2]级别的中间结果  
- **PTWc_3（第三级）**：4-way组相联，缓存VPN[1]级别的中间结果

每个子表都有独特的哈希函数，采用LSB低位有效策略：
```cpp
// LSB 低位有效策略: va_segment[5:0] XOR gscid[5:0] XOR pscid[5:0]
uint32_t va_low = static_cast<uint32_t>(tag.va_segment) & mask;
uint32_t gscid_low = static_cast<uint32_t>(tag.gscid) & mask;
uint32_t pscid_low = tag.pscid & mask;
return (va_low ^ gscid_low ^ pscid_low) & mask;
```

#### WalkerCache查询策略改进

**新增** WalkerCache实现了三重缓存查询策略，模拟并行查询的统计效果：

1. **串行全查**：查询所有三级Cache，不提前退出
2. **仲裁机制**：按C3 > C2 > C1优先级选择最高级命中
3. **延迟计算**：命中时只计最高级延迟，未命中时累加各级延迟

```cpp
// 查询所有三级 Cache，模拟并行查询的统计效果
WalkerData data_c3, data_c2, data_c1;
sc_time lat_c3 = SC_ZERO_TIME, lat_c2 = SC_ZERO_TIME, lat_c1 = SC_ZERO_TIME;

// 查询 C3
hit_c3 = ptw_c3_->lookup(...);

// 查询 C2  
hit_c2 = ptw_c2_->lookup(...);

// 查询 C1（仅 Sv48 模式）
if (!sv39_mode_ && sv48_flag) {
    hit_c1 = ptw_c1_->lookup(...);
}

// 仲裁：按 C3 > C2 > C1 优先级选择最高级命中
if (hit_c3) {
    out_data = data_c3;
    hit_level = 3;
    latency = lat_c3;
} else if (hit_c2) {
    out_data = data_c2;
    hit_level = 2;
    latency = lat_c2;
} else if (hit_c1) {
    out_data = data_c1;
    hit_level = 1;
    latency = lat_c1;
} else {
    latency = lat_c3 + lat_c2 + lat_c1;  // 全未命中：延时累加
}
```

#### 缓存污染预防机制

**新增** WalkerCache实现了关键的缓存污染预防机制：

在`update_entry`方法中增加了无效数据检查：
```cpp
// 关键修复：跳过无效数据的缓存写入，防止缓存污染
// 如果WalkerData.valid=0，说明PTW没有缓存该层级的中间结果
// 不应将(next_ppn=0x0, valid=0)写入缓存，否则后续LOOKUP会错误HIT
if (!data.reserved.valid) {
    printf("[t=%llu ns][WALKER_CACHE] SKIP UPDATE: %s, gscid=%u, pscid=%u, level=%d, va_segment=0x%lx (valid=0)\n",
           (unsigned long long)sc_core::sc_time_stamp().value()/1000,
           cache_name_.c_str(), tag.gscid, tag.pscid, tag.level, tag.va_segment);
    fflush(stdout);
    result.updated = false;
    result.latency = SC_ZERO_TIME;
    return result;
}
```

#### WalkerCache更新机制

**新增** WalkerCache支持多种更新模式：

- **PTWC_1_2_3**：同时更新所有三个子表
- **PTWC_2_3**：仅更新PTWc_2和PTWc_3
- **PTWC_3**：仅更新PTWc_3

更新过程支持两种模式：
- **同步模式**：直接写入，PTWc_1使用直接写入（direct_write=true）
- **异步模式**：通过SystemC进程并行更新多个子表

## 性能考量
- 替换策略
  - pLRU（Tree-based）：适合高并发场景，开销小，适用于DC/PC/MSIPT等中等规模缓存。
  - SRRIP（Static RRIP）：适合PT/Walker等大规模缓存，M位RRPV控制替换偏好，提升命中率。
- 仲裁与延迟建模
  - CacheBase内置WRR仲裁，lookup/fill/invalidate三类操作按权重轮转，避免饥饿；仲裁阶段与各阶段时延可配置。
  - 通过CacheConfig中的hash/read_set/compare/fill_compute/write等cycles参数精细建模。
- 预取与命中率
  - 支持预取标记，统计预取命中率与准确性，有助于识别热点与优化预取策略。
- 配置调优
  - sets与ways：PT/Walker通常增大sets与ways以降低miss；DC/PC/MSIPT可适度减小以节省面积。
  - replacement：PT/Walker建议使用SRRIP；直接映射（1-way）无需替换策略。
  - srrip_m_bits：SRRIP的M值越大，对近期访问更敏感，适合波动较大的工作负载。
- **新增** WalkerCache性能优化
  - 三重缓存查询策略提升了查询效率，通过仲裁机制确保最高级命中结果的优先级。
  - 缓存污染预防机制避免了无效中间结果对缓存的污染，提高了缓存的可靠性。
  - 并行更新机制通过SystemC进程实现了多子表的并行写入，减少了更新延迟。

## 故障排查指南
- 命中率异常下降
  - 检查sets/ways配置是否过小；确认替换策略是否合适（PT/Walker建议SRRIP）。
  - 分析预取命中率与准确性，评估预取策略有效性。
- 失效不生效或级联缺失
  - 确认DC/PC失效后是否正确返回gscid/pscid并触发PT/Walker/MSIPT失效。
  - 检查失效模式（PRECISE/SCAN/GLOBAL）与参数（has_gscid/has_pscid/has_iova）。
- 延迟过高
  - 检查仲裁权重与仲裁阶段时延；核对hash/read_set/compare/fill_compute/write等时延配置。
  - 关注队列延迟直方图，定位瓶颈阶段。
- 统计缺失或异常
  - 确认StatsCollector输出文件路径与任务跟踪级别；检查是否启用延迟直方图与任务跟踪。
- **新增** WalkerCache相关问题
  - 检查缓存污染预防日志，确认是否有大量无效数据被跳过更新。
  - 分析三重查询策略的命中分布，确认仲裁机制是否正常工作。
  - 验证并行更新机制，检查SystemC进程的执行情况。

## 结论
本缓存子系统通过统一的CacheBase模板与顶层CacheSubsystem协调器，实现了DC/PC/PT/MSIPT/Walker五级缓存的高效协同。其关键优势在于：
- 明确的一致性与级联失效机制，确保翻译正确性；
- 可插拔的替换策略与精细的时延建模，便于性能调优；
- 统一的统计与报告体系，支撑命中率分析与瓶颈识别；
- 清晰的配置接口，便于在不同工作负载下进行参数优化。

**更新** 本次WalkerCache的重大改进进一步提升了缓存系统的性能和可靠性，包括三重查询策略、仲裁机制和缓存污染预防等特性，为复杂的页表遍历场景提供了更好的支持。
