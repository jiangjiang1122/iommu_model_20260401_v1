# 16盘实测数据回放扩展方案（real16_trace_replay）

> 本文档为 16 盘实测回放扩展的正式设计文档（由 2026-10-22 批准的计划整理，并补充实施验证结果）。
> 前置文档: [8盘实测_数据回放_仿真_decc545c.md](8盘实测_数据回放_仿真_decc545c.md)。

## 一、任务来源与目标

在既有 real8_trace_replay（8盘实测Excel回放）基础上新增独立测试项 real16_trace_replay，扩展 16 设备：

1. 组B数据 = 组A的 **request id 逐行+8** 虚拟副本（len/addr 不变，不落地 `_1.xlsx` 文件）；
2. 模型映射 device id 0~15（16 个不同 device id 对应 16 个不同 GSCID=1..16）；
3. 读/写方向对两组文件**逐包交替轮询**注入（A[0],B[0],A[1],B[1]…），模拟 16 设备公共交错发包；
4. **两组 4KB 页映射完全独立**：地址即使相同也必须映射到不同 4KB 页，不能复用；
5. 每文件取前 10000 包，共 **40000 包**下发 IOMMU；
6. 独立新增测试项，不影响现有测试项，**不修改 iommu/ 文件夹下任何代码**；
7. 输出全部 37 项固定指标，并与 8盘基线（IOPS 226.631 Mreq/s、读写端口平均带宽 56.459 GB/s）对比。

用户确认的两个设计点：轮询粒度=逐包交替；组B=内存虚拟生成。

## 二、已核实基线与硬约束

**8盘基线出处（对比锚点）**：`rwsplit_results/real8_trace_20261022_100602/real8_run_perf.md`
- 第1项 IOPS 稳态 ALL=**226.631** Mreq/s；第3/4/5项：聚合112.919 GB/s、读口64.001（util 100%）、写口48.917 GB/s → 读写端口平均带宽=(64.001+48.917)/2=**56.459 GB/s**；N=20000，W=(17301.125, 87900.500] ns。

**硬约束（决定技术路线）**：
1. `TEST_CFG_REAL8_TRACE_REPLAY` 宏在 iommu/ 侧既有 `#if`（占用采样钩子）也有 `#if !`（关闭默认统计路径）两类隔离 → **16盘构建必须继续定义该宏为1**，才能不改 iommu/ 任何文件。该宏实际语义为"trace replay 场景宏"，命名沿袭。
2. 多设备框架 N=16 有先例：`test_rp_rand4k_msi_mix_multidev_mc_thread.cc` 同款 `spa_offset(d)=0x80000000+d*0x10000000`（合成校验地址）；GSCID=d+1∈1..16 未超字段宽。
3. 页表预算 require 内建：16设备×(256+8+16)页×4KB≈17.9MiB ≤ 32MiB DDR。
4. IOVA 池 131069 页单池单游标：两组页需求上界≈10044 ≪ 池容量，耗尽保护保留。

## 三、总体设计：纯新增独立测试项

新增 6 个文件，全部独立；唯一被修改的既有文件是 Makefile（仅插入新 else-if 分支）：

| 文件 | 作用 |
|---|---|
| `rp/prepare_real16_trace.py` | 解析2份原xlsx → 4份CSV（组A did0..7、组B did8..15虚拟生成）+ `real16_manifest.json` |
| `rp/test_rp_real16_trace_replay_thread.cc` | 16设备回放主场景（复制改造自real8版，834行） |
| `rp/analyze_real16_trace.py` | 37项固定指标离线分析 + 16盘专项验收断言 |
| `rp/compare_real16_vs_real8.py` | 与8盘基线报告逐项对比表 |
| `run_real16_trace.sh` | 一键流水线：预处理→构建→阶梯→正式→分析→对比→归档 |
| `Makefile` 插入 `real16_trace_replay` 分支 | real8 分支后、msi_perf 分支前，不动任何旧分支 |

**不改**：iommu/ 全部代码、`default_config.json`、所有 `rp/test_rp_*` 旧测试、`prepare/analyze_real8*`、`run_real8_trace.sh`、根 `build/`、既有结果目录。

## 四、数据口径（prepare_real16_trace.py）

1. **组B虚拟生成**：解析原 xlsx 得到 records 后直接复用同一份解析结果产出第二组 CSV（不二次解析、不落xlsx），仅 did+8（205→8、206→9、207→10、208→11、211→12、212→13、213→14、214→15，与组A顺序一一对应）。len/addr/行序/包长与组A逐行相同。manifest 声明"组B=组A虚拟副本(request id+8)"。
2. **输出**：`real16_input/{read_trace.csv, write_trace.csv, read_trace_1.csv, write_trace_1.csv}` + `real16_manifest.json`。CSV 10列格式与 real8 完全一致（组别由 did≥8 隐含，不加列）。
3. **取包**：`--limit 10000` 默认，4份CSV各取前10000行、保持行序；总注入=40000包。
4. **manifest 统计**：16设备逐设备行数/字节、两组源页(page_no)集合交集数、页需求上界=两组独立计算之和（实测：重叠源页 2513，上界 10044）。

## 五、test_rp_real16_trace_replay_thread.cc 核心改造点

1. `N=TEST_CFG_NUM_DEVICES=16`；类名/日志前缀 `Real16TraceScenario`/`[REAL16_*]`；`require(N==16)`。
2. **轮询合并加载**：环境变量 `REAL16_READ_CSV/READ_CSV1/WRITE_CSV/WRITE_CSV1`。每方向先分别加载组A、组B两个 vector，再逐包交替合并进 `recs[dir]`：`A[0],B[0],A[1],B[1]…`，`require(两组等长)`；合并前后打印统计。
3. **两组独立4KB映射（需求核心）**：
   - `Rec` 增 `group = (did>=8)?1:0` 字段；
   - 页表键复合化：`pkey(group, page_no) = (uint64_t(group)<<32) | page_no`；`Generation` 增 `group` 字段；
   - 组内语义与8盘完全一致（同组跨设备/跨方向仍按原始页基址共享一代）；**跨组同原始地址必得不同 generation、不同 IOVA 页**；
   - IOVA 池维持单池+单游标 `pool_next` 顺序分配 → 跨组页号天然全局不重复。
4. **setup()**：N=16 自动覆盖；DID=d、**GSCID=d+1∈1..16**、PSCID=0；每设备 VS 512MiB 全范围建表 + 50×2MiB G-stage；`require(readback.iohgatp.GSCID == d+1)`。
5. **稳态窗口**：total_requests=40000 → steady_start_count=4000、steady_end_count=36000（10%/90% 自动）；W样本=32000。
6. **模型侧产物文件名**全部 `real16_*` 前缀（调用 `top.open_real8_*_trace`/`set_operations_path` 传新文件名，iommu 侧零改动）。
7. 其余同构：双端口 `axi_master_to_pcie_noc_0/0w_socket`、结束条件、watchdog、`[REAL16_RESULT] PASS`、finish 自检 require。

## 六、Makefile 新分支

`else ifeq ($(TEST), real16_trace_replay)`：REAL16_N=16、PTW=64、BUFFER=320、GLOBAL=640、READ/WRITE=320、SLINK=50、DDR=100、`BUILD_ROOT=build_real16`、`TARGET=iommu_model_real16`、`TEST_THREAD_SRC=rp/test_rp_real16_trace_replay_thread.cc`、`-DTEST_CFG_REAL8_TRACE_REPLAY=1`。
固定配置与8盘基线完全一致（SPLIT=1、去重256、PTW64、Buffer320、R/W/G=320/320/640、ADM=1、D=3、Walker Cache开、每设备写保序、R/W口各64GB/s、DDR链路200ns）——保证 16vs8 为"设备数/负载"单变量对照。

## 七、analyze_real16_trace.py 与 16vs8 对比

1. **复制适配**（从 real8 版）：文件名换 `real16_*`；manifest N=40000、W样本32000；37项口径、`ConcIntegrator`/`PageIntegrator` 沿用；第11项4KB页并发按 (DID,映射后IOVA页) 去重时间积分。
2. **16盘专项验收（硬门禁）**：
   - 两组独立性断言：组A与组B的 mapped_page 集合交集=0；同一原始页在两组的 gen_id 必不同；pool_used ≤ manifest 上界；
   - 轮询顺序抽查：requests.csv 前8条 did 组序呈 A/B 交替；
   - 16设备逐设备注入/完成/字节对账闭合 + Jain fairness（附录，不作PASS条件）。
3. **对比报告** `real16_vs_real8_compare.{md,csv}`：37项 × [16盘 | 8盘 | 差值 | 比值]；尾部分三段归因（预期持平/预期变化/异常警示）。

## 八、run_real16_trace.sh 流水线

`bash run_real16_trace.sh [--fresh-build|--skip-build|--ladder|--archive]`：
环境检查 → `make TEST=real16_trace_replay -j`（build_real16/ 全新对象根）→ 阶梯冒烟（可选，`--limit 1000`）→ 正式 `--limit 10000`（40000包，`grep REAL16_RESULT] PASS` 硬门禁）→ 37项分析（16盘专项三项硬门禁）→ 16vs8 对比 → `--archive` 归档 `rwsplit_results/real16_trace_<run_id>/`。

## 九、实施验证结果（2026-10-22 完成）

**构建与冒烟**：WSL 全量编译通过（独立对象根 build_real16/）；`--limit 1000`（4000包）PASS，gen_created=688=344重叠页×2 证明独立映射生效。

**正式仿真（40000包）**：`[REAL16_RESULT] PASS expected=40000 completed=40000`，响应字节逐项对账闭合，pool_used=5176 ≤ 上界10044。

**16盘专项验收（全过）**：
- 组间 mapped_page 不相交：组A=2588页、组B=2588页、交集=0（remap.csv 实证：同原始页 1047046 → 组A gen1/页130378 vs 组B gen3/页42613）；
- 轮询组序 [0,1,0,1,…] 交替正确；
- did 集合 {0..15}、GSCID 集合 {1..16}；16设备对账闭合，Jain=0.804（Excel requester 固有分布）。

**关键性能结论**（W=(30289.750, 184018.500] ns）：
- 稳态 IOPS ALL=**208.159** Mreq/s（8盘 226.631 的 91.85%）；读写端口平均带宽=**52.487 GB/s**（8盘的 92.96%）；
- 全局并发 util 94.85%（8盘 88.36%）、写口并发 full 35.53%、Buffer 占用 97.69%——瓶颈更饱和；
- 两组独立映射使有效页数翻倍（2531→5062）→ Walker C3 7.70% vs 14.33%、S2 C3 37.98% vs 67.32% → PTW 主/预取 DDR 次数 +3.3%/+21.8% → PTW 延时 +8.3% → DATA e2e +16.6%；
- 4KB页平均并发 86.225 vs 75.899（仅+13.6%）：总映射页数精确 2×（5062=2×2531），但吞吐受 IOMMU 内部瓶颈限流（208 vs 227 M/s），40000 包需 2.18× 时间发完，页流密度不变 → 按"页密度×页驻留时间"（Little 定律）并发页同量级，符合物理预期，非统计缺陷；
- 异常偏离警示：**无**。

**零影响回归（通过）**：
- `git diff Makefile`：本次改动恰好只有 real16 分支；
- 512B 基线重跑：PC=2ns（HEAD版配置）口径下与 8盘回归 post **287.02 M/s 逐位一致**（BITWISE_MATCH=True）；PC=1ns（当前工作区配置）口径下与用户锚点 **286.90 M/s 逐位一致**；0.04% 差异根因=default_config.json PC 段在 8盘回归后被改回 1ns（既有配置改动，与16盘无关）；
- `iommu_model_real8`/`iommu_model_regress` 未被重建或覆盖，既有结果目录只读。
